# Collection Panel

The full-screen Item/Skill catalog: filter state, the pure view-state reducer, grid virtualization and cell fit, filtering rules, the Day gate, the source catalog, and card view models.

CollectionPanel is a full-screen Item/Skill catalog mounted by `CollectionPanelMount`, registered with the shared Overlay Panel Host (`src/BazaarPlusPlus/BppComposition.cs`). Its filter state is pure mutable data: active tab/card type, nullable concrete `SelectedHero` (`EffectiveHero` falls back to `Common`), tiers, tags, hidden keyword tags, Any/All facet modes, sizes, selected source key, run-day filter, and sort priority (`src/BazaarPlusPlus/Game/CollectionPanel/Data/CollectionFilterState.cs`). The tab model contains only `Items` and `Skills` (`src/BazaarPlusPlus/Game/CollectionPanel/Data/CollectionTabKind.cs`).

All filter, search, and catalog state transitions are centralized in the pure `CollectionViewState` reducer: panel command methods are single-line forwards, each returning a `CollectionRenderOutcome?` (`null` = same-value no-op) that the panel consumes at its single `ApplyOutcome` point; grid read-back goes through the injected `ICollectionGridPort`, and hero normalization on catalog accept never writes the hero preference (`src/BazaarPlusPlus/Game/CollectionPanel/CollectionViewState.cs`; behavior tests in `tests/CollectionViewState.Tests/`; load-bearing contract points in ADR-0005).

Collection creates one native-card-preview scope for each Unity runtime and gives its virtualizer only that scope. Realized cells retain opaque sessions, not native component/kind/setup-task tuples; stale acquisitions are disposed immediately (`src/BazaarPlusPlus/Game/CollectionPanel/CollectionPanel.cs`, `src/BazaarPlusPlus/Game/CollectionPanel/Grid/CollectionGridVirtualizer.cs`). Runtime teardown waits for pending binds and scope disposal before destroying the overlay and Collection-owned art/material caches (`src/BazaarPlusPlus/Game/CollectionPanel/CollectionPanel.cs`). Collection-specific tooltip registry, cache refcount, and shared-material cleanup remain in its owner adapter and destroy patch, outside the generic preview host.

Collection cards open a modal inspection on left or right click; dragging or scrolling cancels a left click. `CollectionLockVariantPanelPatch` extends native tier/enchantment controls to registered Collection cards when the client supports them. `CollectionInspectionModule` owns an independent preview, suspends Collection input, and closes on Escape or clicks outside those controls. `CollectionInspectionState` rejects stale preview completions and prevents dismissal click-through; `NativeInspectionPresentation` restores borrowed native canvases and raycasters on release. The artwork rectangle stays fixed across tier, enchantment, and description changes until close or viewport resize. Activate the preview behind its alpha gate before measuring the exact native artwork; pooled frame descendants must never affect its fit (`src/BazaarPlusPlus/Game/CollectionPanel/CollectionInspectionModule.cs`; `src/BazaarPlusPlus/Game/CollectionPanel/CollectionInspectionLayout.cs`; `src/BazaarPlusPlus/GameInterop/CardPreview/NativeCardPreviewArtworkMeasurement.cs`; `src/BazaarPlusPlus/GameInterop/Tooltips/NativeInspectionPresentation.cs`; `src/BazaarPlusPlus/Patches/CollectionPanel/CollectionLockVariantPanelPatch.cs`).

Cell measure/fit is split out of the virtualizer: `CollectionCardFitMath` is pure fit math (scale plus anchored position), `NativeCardCellFitter` is the Unity measurement adapter (frame-container → raw-image → aspect-fallback → rect chains), and `NativeCardCellBoundsCache` caches per-cell visual bounds with three invalidation hooks (rebind, scale-dirty, art-load completion) so the scroll path repositions with `allowMeasure: false` instead of remeasuring every realized cell each frame (`src/BazaarPlusPlus/Game/CollectionPanel/Grid/CollectionCardFitMath.cs`, `src/BazaarPlusPlus/Game/CollectionPanel/Grid/NativeCardCellFitter.cs`, `src/BazaarPlusPlus/Game/CollectionPanel/Grid/NativeCardCellBoundsCache.cs`, `src/BazaarPlusPlus/Game/CollectionPanel/Grid/CollectionGridVirtualizer.cs`).

Filtering is code-owned and deterministic. `CollectionFilterEngine.Apply()` applies active card type, excludes package cards from normal results, applies source offer pool membership, hero, tier, day, tag, keyword, and size filters, then sorts by tier/size priority plus localized display name (`src/BazaarPlusPlus/Game/CollectionPanel/Data/CollectionFilterEngine.cs`). Tag and keyword facets support `Any` and `All` matching, and the UI exposes mode toggles in the tag and keyword headers (`src/BazaarPlusPlus/Game/CollectionPanel/Ui/CollectionPanelView.Tree.cs`).

The Day gate consumes only the shared GameData result's `MaximumTier`; absent, not-ready, missing, invalid, and out-of-run results fail open. The manual Tier filter remains an independent AND condition, fixed-tier sources suppress only the Day gate, and Legendary starting tiers retain the game's Diamond compatibility alias (`src/BazaarPlusPlus/Game/CollectionPanel/Data/CollectionFilterEngine.cs`, `src/BazaarPlusPlus/Game/CollectionPanel/Data/CollectionFilterContext.cs`).

Merchant and trainer source filtering is driven by an embedded `collection-sources.json` catalog. Mismatched `collection-sources.json` schema versions are rejected during build/parse (`src/BazaarPlusPlus/Game/CollectionPanel/Sources/CollectionSourceCatalog.cs`). Each source has `offerSegments`, and each segment parses a typed rule with hero mode, starting tier, sizes, tags, hidden tags and groups, enchantability, and enchantment facets (`src/BazaarPlusPlus/Game/CollectionPanel/Sources/CollectionSourceCatalog.cs`).

Card VMs project base card tags and per-enchantment facets from game templates. Lifesteal is derived when an item has positive Lifesteal base value at any tier even if the template lacks the hidden tag (`src/BazaarPlusPlus/Game/CollectionPanel/Data/CollectionCardVm.From.cs`, `src/BazaarPlusPlus/Game/CollectionPanel/Data/CollectionDerivedKeywordFacts.cs`).

Collection and EventPreview share `BppStaticCardMapProvider`, which normally uses the native `GetCardMap()`. `CardTemplateValueCompatibilityPatch` prepares the native thread-local card serializer for both bulk and point lookups. `CompatibleCardValueConverter` prefers native value implementations and supplies `TReferenceValueUniqueCardCount` only when the client cannot deserialize that discriminator. It counts distinct template IDs while inheriting native target selection, default values, modifiers, and rounding; it does not register a global discriminator or alter GameData on disk (`src/BazaarPlusPlus/GameInterop/StaticCards/`).

Other unknown derived types remain unsupported. If native bulk loading encounters one, `CompatibleCardMapReader` reads the same database in read-only mode with the same value compatibility adapter and omits only unsupported templates. This partial snapshot does not replace the game's cache; malformed data and wholly unsupported catalogs still fail. `static_cards.catalog.unsupported_templates` records accepted and unsupported counts.

## Art load degradation and retry

A failed art bind reports `collection_panel.card_art.degraded` with `status=ArtUnavailable`, storm-keyed on `reason_code` (`src/BazaarPlusPlus/Game/CollectionPanel/Grid/CollectionCardArtCache.cs`). The family has one code per silent exit of `CollectionItemLoadArtPatch.LoadArtFromCache`: `CardDataMissing`, `ArtKeyMissing`, `ArtAssetMissing` (cache miss or failed Addressables load), `CardMaterialMissing` (SO without a material), `MaterialMissing` (material construction failed), `CardTextureMissing` (the SO's material has a null main texture), `CardImageMissing` (the card lost its RawImage slot, so neither texture nor material can reach the screen), and `CachedLoadFailed` for an exception on the path (`src/BazaarPlusPlus/Game/CollectionPanel/CollectionPanelLogCodes.cs`). The event names the `art_key` whenever one is known.

A failed artKey is suppressed for 60 s (`CollectionCardArtCache.FailureRetryDelay`), not permanently: the panel can stay open for hours and cells rebind on every scroll, so a permanent blacklist would turn one transient failure — the catalog still warming, a load cancelled by teardown, memory pressure during a fast scroll — into a blank card for the rest of the session. Suppression is per artKey, expires lazily on the next attempt, and a retry costs one Addressables request; the degraded event is storm-suppressed, so retrying cannot flood the log. The window uses `DateTime.UtcNow`, so a device time-zone change cannot move it.

That window is per cache instance. Every `Open()` constructs a new `CollectionCardArtCache` and `DisposeAll()` clears the failed set, so it does not span panel open/close cycles. `CollectionCardArtCache.ClearFailedKeys()` is the in-session escape hatch: `CollectionPanel.InvalidateCatalog` calls it on locale change (through `NotifyLocaleChanged`) and on runtime dispose (where the caches are already gone, making it a no-op), so cards rebound after a catalog invalidation retry immediately instead of waiting out the TTL. It is never called per frame.

Clearing the failure window is not enough on its own: every failure exit also calls `ClearCachedMaterialAssignment`, and pool release (`CollectionNativeCardPreviewOwner.ReleaseOwnedState`) clears `_cardImage.texture` and `_cardImage.material` before releasing the art refcount. Without that, a pooled card keeps drawing the previous item's art and would still point at a texture or shared Material the cache destroys on eviction.

## Gotchas

Traps and rules that bite only this feature; most failed silently at least once.

- Android's mobile tray and its nested description canvas need distinct sorting orders: flattening both to one order composites the tray's dark background over otherwise fully opaque text. `NativeInspectionPresentation.PromoteDescriptionCanvas` leases only the description above the tray, without detaching its scaler or scroll mask, and restores it before its parent. [`src/BazaarPlusPlus/GameInterop/Tooltips/NativeInspectionPresentation.cs`]

- UI Toolkit `Button` inherits `TextElement`, so `Q<TextElement>()` returns the button itself when no separate label exists — hiding that "label" hides the whole control (guard with `!ReferenceEquals`), and a refresh writing `Button.text` resurrects the native label beside a custom one. [`src/BazaarPlusPlus/Game/CollectionPanel/Ui/CollectionPanelView.Filters.cs`]
- The hardcoded `DayTierSchedule` was removed — do not restore it as a fallback. Day tiers resolve through `GameDataDayTierResolver`, whose success cache is keyed on `JsonGameDataManager` reference identity because the game swaps that reference after a GameData download. [`src/BazaarPlusPlus/GameInterop/DayTiers/GameDataDayTierResolver.cs`]
- Aspect-fallback collection cards (no measurable frame or raw-image bounds) hold size via a one-shot `SetSizeWithCurrentAnchors` plus the per-cell bounds cache. This path shipped without in-game smoke; on card-size drift, apply the fallback documented in the fitter header. [`src/BazaarPlusPlus/Game/CollectionPanel/Grid/NativeCardCellFitter.cs`]
- CollectionPanel source filtering runs off the embedded `collection-sources.json`, and the catalog size is pinned by the source/merchant/trainer count assertions in its test — adding a source means updating those expectations too. [`src/BazaarPlusPlus/Game/CollectionPanel/Sources/CollectionSourceCatalog.cs` | `tests/CollectionSourceFiltering.Tests/Program.cs`]
